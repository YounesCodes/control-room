A connection saves a host's SSH address and username, and optionally a port and a private key. The address can also be a host name from your `~/.ssh/config`. Control Room uses the key where it is and never copies it.

**Test structured access** checks that the host views can sign in without a password prompt.

Control Room uses the OpenSSH client on your computer, so your keys, `~/.ssh/config`, and ssh-agent work as usual. On Linux and macOS, the host views share one SSH connection and close it after a minute of no use. This replaces any `ControlMaster` setting in your SSH config for those views. Terminals always open their own connection.

If you change the address, username, port, or key, Control Room forgets what it learned about the old host. Open terminals stay connected until you reconnect.

## Windows and Mac hosts

On Windows and Mac hosts, you choose a shell before the terminal opens.

- **Windows** lists Windows PowerShell, Command Prompt, PowerShell 7, Git Bash, other shells it finds, your Windows Terminal profiles, and each WSL distribution.
- **macOS** lists zsh, Bash, and fish if it is installed.

Listing the shells needs an SSH key or ssh-agent login. Control Room remembers the list and the shell you picked.

The host views always read the host itself. A WSL terminal on a Windows host still shows Windows services and ports.

| Host    | Views                                                |
| ------- | ---------------------------------------------------- |
| Linux   | Terminal, Docker, Systemd, Logs, Ports, History      |
| macOS   | Terminal, Docker, Services, Logs, Ports, History     |
| Windows | Terminal, Docker, Services, Logs (containers), Ports |

## Groups, tags, and deleting

Put a host in a group and give it up to five tags. Groups and tags are saved only on your computer.

**Delete connection** also closes that host's tabs and deletes its saved command history.

If a connection fails, see [Troubleshooting](/control-room/help/troubleshooting/).
