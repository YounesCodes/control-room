A connection saves the SSH address and username for a Linux, Windows, or macOS host. Select it in the sidebar to open a terminal. The first time, the terminal starts while Control Room detects the host's platform. A Linux shell appears as soon as either finishes. Windows and Mac hosts then show the shell picker, and the shell you pick replaces that first terminal.

Select **Add connection** in the sidebar. To change one, open its menu and choose **Edit connection**.

Enter a display name, SSH destination, and username. **Port** (1–65535) and **Private key** are optional; leave them empty to use your SSH defaults. The key stays in its existing location and is never copied into Control Room. Control Room uses your system OpenSSH client and your normal SSH configuration.

**Test structured access** checks whether the inspection views can connect without an SSH password prompt. It does not save the connection. The terminal can still use an interactive password login if that test fails.

On Linux and macOS, the inspection views reuse one SSH connection per target and keep it open for a minute after their last call. Terminals always open their own connection. For inspection calls, this replaces any `ControlMaster`, `ControlPath` or `ControlPersist` setting in your SSH config. Windows opens a new connection for each call.

Changing a connection's destination, username, port, or key clears its cached host facts and inspection results. Open terminals keep their existing sessions until you reconnect. A remote shell selected for the previous target is cleared.

## Transfer files

Open a saved host and select **Files** in the sidebar. The browser starts in the SSH account's home folder. Open a folder to browse it, or use **Parent folder** and **Home folder** to go back. Enable **Show hidden files** to see names beginning with a dot.

Select **Upload files** to choose one or more local files, or drop them into the open folder. Dropping files on a host terminal uploads them to that account's home folder, including when the terminal is in a split. To download, select a file in **Files** and choose a folder on your computer.

**Transfers** shows progress, speed, and a cancel button. You can switch views while files copy. When a file already exists, select **Review** to replace it or keep the existing copy.

Transfers use SFTP with your saved SSH connection. The host must enable SFTP and accept your key or SSH agent without a password prompt. Choose individual files for transfer. On Windows hosts, a path such as `/C:/Users/Lee` refers to the account's Windows files.

## Windows 10 and 11 hosts

Enable the Windows OpenSSH Server and save the host as a normal SSH connection. Shell detection needs an accepted host key and key or agent authentication that works without a prompt.

When you open a new terminal for a Windows host, choose a shell from the grouped list. It offers Windows PowerShell, Command Prompt, PowerShell 7 and Git Bash when found, other supported shells on the account's PATH, and each available WSL distribution. Select **Connect** to open that shell inside Control Room. Control Room saves the list with the host's details, so after the first detection the picker opens with the saved list at once and checks for changes in the background. **Refresh available shells** checks right away.

Installed Windows Terminal profiles that launch a supported shell also appear in the picker. The profile's command and arguments run over SSH. Its graphical window, colors, and other desktop settings remain in Windows Terminal.

Reconnect and restored tabs reuse their chosen shell. **New terminal** lets you choose another shell on the same host. If a selected shell was removed, open a new terminal and choose an available one.

Windows hosts offer Terminal, Files, Services, Ports, Docker, and container Logs. Scratchpad opens from the terminal toolbar. Docker has its own sidebar entry, as on Linux hosts. Docker and Logs require the Windows Docker CLI and daemon access for the SSH account; their views report when either is unavailable. Optional header metrics show Windows resource readings. Inspection always reads Windows itself, including when the terminal runs WSL. WSL uses the distribution's default user and shell. Enhanced History is unavailable on these connections.

## macOS hosts

Enable **Remote Login** in macOS System Settings and allow your SSH account. Save the Mac like any other SSH host. Shell discovery and inspection require an accepted host key and key or agent authentication that works without a prompt.

Choose zsh, Bash, or an installed fish shell, then select **Connect**. Once the Mac's details are saved, the picker opens with the saved shell list and checks for changes in the background. Reconnect and restored tabs retain the selected shell. Mac hosts offer Terminal, Files, Services, Ports, Docker, Logs, History, and Scratchpad. Inspection reads macOS even when another shell is selected.

The SSH account can inspect its own launchd agent domains and the system service inventory. Reading other processes, protected logs, or Packet Filter rules may need sudo. Docker requires an installed CLI and an accessible daemon in the account's selected Docker context.

## Organize and remove hosts

Put a connection in one group and add up to five tags to help find it. Groups and tags are stored on your computer; they do not change the host. Search finds names, addresses, groups, and tags.

**Delete connection** also removes its open host tabs and saved command history. Local terminal tabs are unaffected.

If SSH or the access test fails, see [Troubleshooting](/control-room/help/troubleshooting/).
