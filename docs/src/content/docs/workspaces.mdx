---
title: Workspaces
description: Understand remote and local Workspaces, persistence, tabs, and splits.
---

A Workspace is one open view of one target. A remote Workspace belongs to a Saved Connection. A local Workspace belongs to one Local Shell Profile.

## Remote Workspaces

A remote Workspace groups one SSH Terminal Session with the inspection views supported by the Remote Host. The navigation includes Overview, Terminal, Systemd, Ports, Docker, Boot, Logs, Baselines, History, and Scratchpad.

You can open several Workspaces for the same Saved Connection. Their sessions, view choices, and reconnect lifecycle stay separate.

## Local Workspaces

A local Workspace is terminal-only: one installed Windows shell with the same tabs, splits, and
terminal settings as a remote Workspace, and none of the host views.

## Restore after restart

Control Room saves Workspace identity, active view, Enhanced History pause state, and focus-mode terminal groups locally. On restart:

- each restored remote Workspace opens a fresh SSH session
- each restored local Workspace starts a fresh shell
- a failed start stays visible with Reconnect or Restart available
- a deleted Saved Connection removes its remote Workspace
- a shell that is no longer installed is dropped
- old saved state that predates Local Terminal still restores as a remote Workspace

Control Room restores the tabs and layout, then starts new sessions. It does not restore terminal output or a previous shell process.

## Labels and focus

When several Workspaces share a target, Control Room adds a number to their display labels. Focus mode hides the connection rail and title bar and shows standalone terminal tabs alongside named split groups. A group can mix Workspaces from several remote hosts and local shells. Leaving focus mode returns to the active Workspace and its inspection views.
