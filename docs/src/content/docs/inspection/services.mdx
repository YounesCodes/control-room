On a Linux host, **Systemd** lists the host's services, timers, sockets, and other units. Failed units come first. This view only reads. It never starts or stops anything.

- **Focused** hides routine system units. Choose **All units** to see everything.
- Select the failed count to show only failed units.
- **Find units** searches by name. **Filter and sort units** filters by state and type.

Select a unit to see its details. Use **Up** and **Down** to move to the next unit. Expand **Configuration** to read the unit file, or **Advanced** for everything else systemd reports. Values that systemd doesn't report show as **Unavailable**. An open service refreshes its memory and runtime details every three seconds.

## Find out why a unit failed

Select a failed unit. **Failure evidence** shows how it ended, such as an exit code or signal. Select **View journal** to read its logs in [Logs](/control-room/inspection/logs/).

## Dependency graph

Choose **Dependency graph** beside **Explorer** to see how a unit relates to others. Pick what the lines mean:

- **Dependencies.** Units this one pulls in. A solid line means it requires the unit. A dashed line means it only wants it.
- **Ordering.** Units that start before or after this one. Arrows point from first to last.
- **Activation.** Units that start this one, such as a socket that starts a service.

Drag to move around and use the wheel to zoom. Double-click a unit to center the graph on it. Use **Expand** to load its neighbors, and **Fit to view** to see the whole graph again. The graph shows up to 25 units.

Systemd shows system units only, not user units. It uses `systemctl` on the host.

## Windows and Mac hosts

On these hosts the view is called **Services**.

- **Windows.** Shows each service's name, status, startup type, and process ID.
- **macOS.** Shows loaded launchd daemons and agents. Running jobs show their process ID. Select **View logs** to read a job's logs.
