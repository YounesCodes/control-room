On a Linux host, **Systemd** lists the host's services, timers, sockets, and other units. Failed units come first. This view only reads. It never starts or stops anything.

By default the list hides routine system units. Choose **All units** to see them. A unit's details include its unit file and everything systemd reports about it. An open service refreshes its memory and runtime details every three seconds.

## Find out why a unit failed

**Failure evidence** shows how a failed unit ended, such as an exit code or signal. **View journal** opens its logs in [Logs](/control-room/inspection/logs/).

## Dependency graph

**Dependency graph** shows how a unit relates to other units, up to 25 at a time. The lines can show:

- **Dependencies.** Units this one pulls in. A solid line means it requires the unit. A dashed line means it only wants it.
- **Ordering.** Units that start before or after this one. Arrows point from first to last.
- **Activation.** Units that start this one, such as a socket that starts a service.

Systemd shows system units only, not user units. It uses `systemctl` on the host.

## Windows and Mac hosts

On these hosts the view is called **Services**.

- **Windows.** Shows each service's name, status, startup type, and process ID.
- **macOS.** Shows loaded launchd daemons and agents. Running jobs show their process ID.
