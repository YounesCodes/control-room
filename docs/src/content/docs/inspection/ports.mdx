**Ports** shows which TCP and UDP ports are open on the host and which service, container, or program is listening on each one. It is a snapshot.

Select a port to see how it is bound, its open connections, the firewall policy, and the program behind it. If it belongs to a container or service, you can jump there with **Open container** or **Open unit**.

- **Filter ports** shows only listeners or only outgoing connections. **Loopback only** shows ports that only this computer can reach.
- **Show established connections** adds open connections that aren't listeners. They have a dashed outline.

## Can other computers reach this port?

Ports can't tell you that for sure, so **Reachability** always says **Not tested**. A port on `0.0.0.0` listens on every network the host is on. Whether other computers get through also depends on firewalls, routers, and Docker. Ports does not scan the network.

Ports shows the host's own firewall next to each port:

- **Linux.** UFW, or numeric port rules in firewalld. Other firewall setups are not read, so a missing rule doesn't mean the port is blocked.
- **Windows.** Whether the firewall is on and its default for incoming traffic. Single rules are not read.
- **macOS.** The Application Firewall and Packet Filter. Packet Filter usually needs sudo.

## Missing owners

Some accounts can't see which program owns a port. The port still appears, with its owner marked unavailable. Select **Resolve owners with sudo** to try again with more access. See [Security](/control-room/reference/security/#sudo).
