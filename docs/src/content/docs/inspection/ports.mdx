Ports takes a snapshot of TCP and UDP listeners on the connected host. It can also show established connections, Docker port mappings, and firewall information.

The graph fills the Ports screen. Select a port or connection to inspect its binding, firewall policy, process, service, remote endpoints, or Docker mapping. Close the details with **Close details** or **Escape**.

Drag the canvas to pan. Use the wheel or zoom buttons to zoom, and **Fit to view** to show the whole graph. Open **Find ports** to search ports, owners, or endpoints. Open **Filter ports** to choose **Listeners**, **Connections**, or **Docker**, or narrow by protocol and exposure. Active search and filters keep their toolbar buttons highlighted. Exposure filters apply to known bind addresses, so they hide connection summaries that have no bind address.

Hover over the listener count beside **Ports** for collection time and connection limits. Keyboard focus exposes the same summary to screen readers. **Ports reading warnings** contains warnings and retry actions. Failed reads open those warnings automatically. Refresh failures keep existing results visible. Published Docker ports and established connections can appear even when no matching listener was reported.

Some accounts cannot read which process owns a socket. The listener still appears, with its owner marked unavailable. On Linux, **Resolve owners with sudo** can retry the read where allowed. Control Room links to a service or container only when it can match it reliably.

A listener on `0.0.0.0` accepts connections on more than one local interface, but that alone does not tell you whether it is reachable from the Internet. Firewall rules and network access are separate. Ports does not scan other machines or test reachability.

The firewall snapshot reads UFW or firewalld. UFW includes its incoming default policy. firewalld reports active zones and explicit numeric port rules, without deciding which zone governs a listener. A failed zone or port read reports an unavailable snapshot instead of an empty rule list. Service-name rules, rich rules, direct rules, and nftables-only or iptables-only configurations remain unavailable. A missing numeric rule does not mean a port is blocked.

On Windows, the view reads TCP and UDP listeners, their available process names and IDs, and established TCP peers. Firewall details show profile enablement and default inbound policies only. Per-port Windows firewall rules and Windows service ownership links are unavailable.

If a Linux firewall read is denied, choose **Retry with sudo** to repeat that read with a password sent once. The app does not save the password or change firewall rules.
