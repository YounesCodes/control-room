Docker shows the host's containers, including stopped ones, in a graph grouped by Docker Compose project. Select a container to zoom to it and open its details.

Known image repositories show a bundled logo, with brand colors on hover, keyboard focus, or selection. Unknown and custom images keep the generic container icon. Logos identify images, not container health.

Use **Find containers** to search by project, service, name, image, or container ID. **Filter containers** offers **Container state** and **Group by**. Choose **None** to give each container its own branch. A container appears under **Ungrouped** when its Compose labels are missing or invalid.

Drag the canvas to pan, use the wheel or zoom buttons to zoom, and select **Fit to view** to frame the graph. Hover or focus **Containers** for counts and collection time. Close details with **Close details**, Escape, another press on the selected container, or a click on empty canvas. Dragging keeps details open.

Details can include:

- name, image reference, and content ID
- running, paused, restarting, OOM-killed, and dead state
- exit code and lifecycle timestamps
- health status and failing streak
- restart policy and maximum retries
- published port summaries and network addresses
- mount destinations
- validated Compose project, service, number, and one-off facts

Select a published binding to open its endpoint in [Ports](/control-room/inspection/ports/), including binding, connection, and firewall evidence. If the publication is absent from the Ports snapshot, the view reports it instead of selecting another listener.

The view does not show environment variables or host mount sources. Select a container's logs to read them in [Logs](/control-room/inspection/logs/). On Linux, if Docker access needs sudo, the view can offer a [read-only retry](/control-room/reference/security/#elevated-reads).

On Windows hosts, **Docker** has its own sidebar entry, alongside **Ports**, and **Logs** offers container logs. These views stay visible even when Docker is unavailable. They use the Windows Docker CLI and that account's Docker context. The daemon must already be running and accessible to the SSH account. If Docker is missing or access fails, the view reports the error. Check Docker and account permissions, then retry. Docker installed only inside WSL is not included.
