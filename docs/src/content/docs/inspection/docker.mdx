Docker lists the host's containers, including stopped ones. Switch between a flat list and groups based on Docker Compose labels. Select a container to see its details.

Search by project, service, name, image, or container ID. A container appears under **Ungrouped** when its Compose labels are missing or invalid.

Details can include:

- name, image reference, and content ID
- running, paused, restarting, OOM-killed, and dead state
- exit code and lifecycle timestamps
- health status and failing streak
- restart policy and maximum retries
- published ports and network addresses
- mount destinations
- validated Compose project, service, number, and one-off facts

The view does not show environment variables or host mount sources. Select a container's logs to read them in [Logs](/control-room/inspection/logs/). On Linux, if Docker access needs sudo, the view can offer a [read-only retry](/control-room/reference/security/#elevated-reads).

On Windows hosts, **Docker** has its own sidebar entry, alongside **Ports**, and **Logs** offers container logs. These views stay visible even when Docker is unavailable. They use the Windows Docker CLI and that account's Docker context. The daemon must already be running and accessible to the SSH account. If Docker is missing or access fails, the view reports the error. Check Docker and account permissions, then retry. Docker installed only inside WSL is not included.

On macOS, Docker uses the SSH account's CLI configuration and selected context. The view shows the context and endpoint. Docker Desktop is one option; an SSH or TCP context can point to another Docker host. Its containers and published ports belong to that daemon. Automatic sudo allowances do not change the account used for Mac Docker reads.
