Download Control Room from the [latest GitHub release](https://github.com/YounesCodes/control-room/releases/latest). To have an AI agent do the setup for you, see [Set up with an AI agent](#set-up-with-an-ai-agent).

## Windows

Control Room runs on 64-bit Windows 11. It uses the OpenSSH Client that comes with Windows. If SSH is missing, turn on **OpenSSH Client** in Windows optional features.

1. Download the `.exe` installer.
2. Run it. It installs for your user and does not need administrator access.
3. Open Control Room from the Start menu.

The installer is not signed, so Windows may warn about an unknown publisher. Select **More info**, then **Run anyway**.

## Linux

Control Room is built and tested for Ubuntu 24.04 LTS on x86_64. Other distributions may work, but they are not tested.

- **Debian package.** Run `sudo apt install ./<filename>.deb` in the folder where you saved it. This also installs what the app needs. Open Control Room from your applications menu.
- **AppImage.** Install `libfuse2t64`, `openssh-client`, and `xdg-utils` if you don't have them. Run `chmod +x <filename>.AppImage`, then `./<filename>.AppImage`. Keep the file in a folder you can write to, so the app can update itself.

If you can't drag the window by its edges, use your window manager's move or resize shortcut.

## macOS preview

There is no macOS download yet. To try the preview, build it on a Mac with macOS 12 or newer. You need Node.js 22.22.2 or newer, Rust stable, and the Xcode Command Line Tools.

```sh
npm ci
npm run tauri build
```

Then open `src-tauri/target/release/bundle/macos/Control Room.app`.

Signed-in GitHub users can also download a test build from the [macOS workflow](https://github.com/YounesCodes/control-room/actions/workflows/macos.yml). These builds are not notarized by Apple, so macOS blocks the first launch. To allow it once:

- **macOS 15 or newer.** Try to open Control Room, then close the warning. Go to **System Settings > Privacy & Security** and select **Open Anyway**.
- **macOS 12 to 14.** Control-click the app, choose **Open**, then select **Open** again.

## What the host needs

The host is the computer you connect to. It needs an SSH server that accepts your login.

- **Linux.** Install an SSH server, such as `openssh-server`.
- **macOS.** Turn on **Remote Login** in System Settings.
- **Windows 10 or 11.** Turn on OpenSSH Server.

The terminal can sign in with a password. The host views, and the shell list on Windows and Mac hosts, sign in on their own in the background, so they can't ask for a password. They need an SSH key or ssh-agent.

On Linux, each host view needs a tool on the host. If a tool is missing, only that view is unavailable.

| View    | Needs                    |
| ------- | ------------------------ |
| Systemd | systemd                  |
| Logs    | journald or Docker       |
| Ports   | `ss` from iproute2       |
| Docker  | Docker, and access to it |
| History | Bash                     |

Control Room recognizes Debian, Ubuntu, Rocky Linux, AlmaLinux, Oracle Linux, CentOS Stream, Amazon Linux 2023, Fedora Server, openSUSE Leap, Arch Linux, and Alpine Linux. Alpine uses OpenRC instead of systemd, so it has no Systemd view.

Windows and macOS hosts use tools that come with the system. On Windows, Docker needs `docker.exe` and a running Docker engine the SSH account can use. Docker that runs only inside WSL is not shown.

## Set up with an AI agent

A coding agent, such as Claude Code or Codex, can do these steps for you. Paste a prompt into the agent on the computer where you'll run Control Room.

To install the app:

```text wrap
Install Control Room on this computer by following https://younescodes.github.io/control-room/start-here/installation/
```

To set up a host, put in its address and your username:

```text wrap
Set up SSH key sign-in from this computer to <username>@<address> for Control Room, and check what the host views need, by following https://younescodes.github.io/control-room/start-here/installation/#what-the-host-needs
```

Agents can read all of these docs as plain text at [llms-full.txt](https://younescodes.github.io/control-room/llms-full.txt), or start from the index at [llms.txt](https://younescodes.github.io/control-room/llms.txt).

## Updates

The Windows installer and the Linux AppImage check for updates while the app is open. When one is ready, a download icon appears in the title bar. Select it to see what changed, then download the update. The app checks the update's signature before it installs it.

**Restart to update** closes your terminals and log streams. Your saved hosts and tabs stay, and the tabs start new sessions after the restart. To check by hand, use **Check for updates** in **Settings > App & Diagnostics**.

The Debian package does not update itself. Select **Open releases** in **Settings > App & Diagnostics**, download the new `.deb`, and install it the same way. Your data is kept.

## Check a download

To make sure a file downloaded correctly, save `SHA256SUMS.txt` from the same release into the same folder. Then run this from that folder:

- **Windows (PowerShell).** `(Get-Content SHA256SUMS.txt) -match (Get-FileHash .\<filename>.exe).Hash` prints a line if the file is good, and nothing if it isn't.
- **Linux.** `sha256sum --ignore-missing -c SHA256SUMS.txt` prints `OK` for a good file.
